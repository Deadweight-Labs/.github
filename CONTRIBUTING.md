# Contributing

Thanks for wanting to help. These defaults apply to every Deadweight Labs repository that has no `CONTRIBUTING.md` of its own. If a repository has its own, follow that one.

## Before you start

1. Search the existing issues first.
2. For anything bigger than a small fix, open an issue before writing code so we can agree on the approach.
3. Create a branch named `feat/…`, `fix/…`, `docs/…` or `chore/…`. If the repository has a `dev` branch, target it with your pull request.

## Pull requests

- Keep each pull request to one change.
- Use [Conventional Commits](https://www.conventionalcommits.org/) for titles, for example `fix(sync): retry on 409`.
- Say what problem the change solves and how you checked that it works.
- Some repositories ask you to accept a CLA. Their pull request template tells you how.

## Security

Never report a vulnerability in a public issue. See [SECURITY.md](SECURITY.md).
